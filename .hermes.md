# Hermes runtime notes

Runtime facts that apply when the agent working here **is** Hermes. Project
rules, product rules and owner preferences come from `/projects/blockwise/AGENTS.md`,
which loads automatically alongside this file. This file adds only what Hermes
needs to know about itself.

## Where things live

| Thing | Path |
|---|---|
| Runtime code | `/home/hermes/.hermes/hermes-agent` |
| Python for every runtime command | `/home/hermes/.hermes/hermes-agent/venv/bin/python` |
| Config | `/home/hermes/.hermes/config.yaml` |
| Logs | `/home/hermes/.hermes/logs/` |
| Session dumps | `/home/hermes/.hermes/sessions/` |
| Durable notes | `/home/hermes/.hermes/memories/MEMORY.md` |
| Owner profile | `/home/hermes/.hermes/memories/USER.md` |
| Semantic memory | `/home/hermes/.hermes/hindsight/` |
| Your own skills, the ones your index lists | `/home/hermes/.hermes/skills` |
| Extra skills shared across runtimes | `/srv/skills` (config `skills.external_dirs`) |
| Quarantined skills, restorable | `/srv/skills-archive/<date>/` |

The runtime runs at its own checkout. Do not edit it in place. Commit, push to
the fork, then sync the checkout.

Two roots hold skills and both appear in your index: your own
`~/.hermes/skills`, whose category folders are what the index groups by, and
`/srv/skills` as an external read-only dir. A skill name in both roots resolves
to the local one. Adding a skill means writing to the local root.

## Things that look broken but are not

- **The Hindsight daemon stops on its own.** It runs with a 300 second idle
  timeout and starts again on the next memory read or write. A stopped daemon is
  normal. Only investigate if it fails to start when used.
- **`hermes memory status` reports `Memory tool: disabled`.** That check tests a
  toolset name that a sentinel value breaks. The memory tool is enabled and
  works. Verify with a real write instead of trusting that line.
- **CLI warnings about unrecognised config keys can be false.** Grep the source
  before acting on one.

## Memory limits, and why they matter

`MEMORY.md` is capped at 2200 characters and `USER.md` at 1375. Both are injected
into the system prompt on every turn, which is why the caps exist. A write that
would push either file over its cap is rejected outright, and the tool cannot
trim for you while you are over. When a write is refused, consolidate in the
same batch: shorten existing entries or remove ones another entry now covers.
Leave headroom rather than filling to the cap.

## Working here

- Run runtime tests with the venv interpreter, never the system one:
  `/home/hermes/.hermes/hermes-agent/venv/bin/python -m pytest <path>`.
- Skills are discovered from `/srv/skills`. Every `SKILL.md` needs YAML
  frontmatter with `name` and `description`, or no runtime will see it.
- Long jobs should report progress as they go, keep bounded retries, and park a
  blocked item with its reason rather than retrying it forever.
- Surface anything that spends money, destroys data, or cannot be undone. Handle
  everything else without asking.
